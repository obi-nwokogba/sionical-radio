SionicalRadio

A beautiful, cross-platform internet radio player. Open a .pls file and it starts streaming instantly - on Windows, Mac Intel, and Mac Apple Silicon.

Python 3.12 on your Mac PySide6 for the GUI libVLC for streaming PyInstaller for installers

1 Setup in PyCharm (Mac, Python 3.12)

1.1 Install the two system pieces

  1. Python 3.12 - from the python.org macOS 64-bit universal2 installer (binary installers for 3.12 stop at version 3.12.10, so that installer is the normal, recommended pick; later 3.12.x releases are source-only security patches). Two reasons to prefer 3.12 over 3.10: Python 3.10 reached end-of-life in October 2026 and gets no more security updates, while 3.12 is patched until October 2028 and is noticeably faster. And the universal2 detail matters later: it is what lets you build one app that runs on both Intel and Apple Silicon Macs.
  2. VLC media player - install it from videolan.org. The app does not use the VLC window; it drives VLC's playback engine (libvlc) behind the scenes. This is needed on your development machine only - the installers you build carry their own copy of the engine (section 5.4), so your users never have to install VLC.
  3. Your fonts (optional) - create a components folder next to SionicalRadio.py and drop in up to five files named exactly font1.ttf, font2.ttf, font3.ttf, font4.ttf, font5.ttf. The twenty-four built-in themes (twelve dark, twelve light) each assign four different fonts to the brand (the SIONICAL RADIO wordmark), title (station name and marquee), body and wire roles (theme 1 uses font4 for the brand, font2 for titles, font1 for body text and font3 for the wire buttons). Missing fonts simply fall back to the system font - the app runs fine without them.
  4. Your icons and logo (optional) - in the same components folder, drop unmuted.svg, muted.svg, heart-outline.svg, heart-filled.svg and next.svg (the mute / love / next circles and the station hearts), plus sionical-radio-logo.png (the window icon at runtime; the build scripts also turn it into the launcher and installer icon). Missing files fall back to the painted shapes built into the app, so nothing here is required.
Already have Python 3.12? Check whether it is the universal2 build: in a terminal run file -L $(command -v python3). If the output contains universal binary, you are set. Homebrew Pythons are single-architecture (arm64 or Intel), which is fine for everyday use - but only the universal2 build can produce the one-app-for-both-Macs installer in section 5.

1.2 Create the project

  1. In PyCharm: File > New Project, choose Pure Python.
  2. Name it sionicalradio. For Interpreter, pick your Python 3.12 and leave "Create a virtualenv" checked - PyCharm gives you a clean, private environment.
  3. Copy two files into the project folder: SionicalRadio.py (the full app source) and requirements.txt (below).

1.3 The exact requirements.txt

These are the exact, pinned versions that work on every target this project ships to. PySide6 6.9.3 runs on macOS 12 or newer, on both Intel and Apple Silicon (its macOS wheel is a universal2 build), on Windows, and on Python 3.9 up - so one pin covers all three build targets. python-vlc is a thin ctypes wrapper, so it works on any Python. pyinstaller is only needed when you build installers, but keeping it here means one command installs everything.

Why not the newest PySide6? PySide6 6.10 and newer ship macOS wheels that require macOS 14.0 or later. On a Mac running macOS 13 or older, pip cannot use them at all and reports "No matching distribution found" for any version 6.10+, while PyCharm's requirement banner keeps reappearing. Check your macOS version with sw_vers -productVersion. Version 6.9.3 is the newest that installs on macOS 12-13, and everything this app uses (Qt Widgets, sliders, QSS styling) is fully supported there.
requirements.txt
# SionicalRadio - runtime requirements (Python 3.12)
PySide6==6.9.3
python-vlc==3.0.21203

# Build-only: needed only when generating the installers
pyinstaller==6.22.3

1.4 Install and run

PyCharm Terminal (venv is auto-activated)
python -m pip install -r requirements.txt

Then right-click SionicalRadio.py and choose Run. You should see the dark SionicalRadio window with fifteen built-in stations. Double-click one - audio should start within a second or two.

PyCharm tip: if import vlc shows a red underline, the package was installed into the wrong interpreter. Check Settings > Project > Python Interpreter - the venv you created must be selected.

2 Running the app

Normal run

Terminal
python SionicalRadio.py

Open a .pls file and play instantly

Three ways - all of them start streaming immediately:

  • Command line: python SionicalRadio.py mystation.pls - the app loads every station in the file and starts playing the first one.
  • Drag and drop: drop any .pls file anywhere over the window - the whole UI is a drop zone.
  • Button: click ADD PLS (bottom right), pick the file, playback starts by itself.

In PyCharm, you can pass the file through a run configuration: Run > Edit Configurations > Parameters and enter mystation.pls.

While listening

  • The status line (bottom left) shows Connecting... then Streaming live.
  • If the station broadcasts "Now Playing" metadata, the marquee line under the station name continuously scrolls the current "Artist - Song" - it always drifts, never sits still, and the line spans the full panel width. The title is read over a plain-http twin of the stream because VLC 3 drops ICY titles on https (see 3.5), so expect the first title a few seconds after playback starts - stations only embed metadata every few seconds of audio. Until it arrives (or if a station broadcasts none) the marquee scrolls a "Waiting for track info" line instead of showing URL-derived labels like "mp3-128".
  • The equalizer bars dance to the real audio - each bar is a single rounded rectangle that grows and shrinks with the music, with no caps on top, painted at 60% opacity and tweened for a smooth bounce (no flicker). The 10 / 20 / 30 / 40 / 50 wire chips above them switch the bar count.
  • Click STATIONS (bottom right) to expand the station list; double-click a station to play it. The big circle is play and stop. Each station row starts with a heart (heart-filled.svg tinted with the accent color when the station is favorited, heart-outline.svg tinted with the text color when not - favorites float to the top of the list) followed by the station name and a subtle X that removes the station. Fifteen stations ship built in; the list scrolls.
  • ADD STREAM lets you paste a raw https://... stream address without a .pls file; the THEME wire button (top right) shows the current theme's name (for example "THEME : SIONICAL BLUE") and cycles the twenty-four themes - twelve dark, twelve light.
  • Under the big play circle sit three smaller circular buttons, exactly as wide as the play button together: MUTE (the unmuted.svg / muted.svg speaker icons; drag the volume bar away from zero to unmute), a HEART that loves the playing station (heart-outline.svg / heart-filled.svg, kept in sync with the row hearts, and loved stations float to the top of the list), and NEXT (next.svg), which jumps to the next station and wraps around at the end. All three draw their SVG icons with 10 px of padding all round, tinted with the theme.
  • The window has no macOS/Windows title bar, and the whole window is one smooth rounded rectangle (25 px corners). The three traffic-light circles at the top left of the panel close, minimize and zoom the window, and dragging anywhere on the panel moves it. Frameless windows cannot be resized by dragging their edges; the green button zooms and restores instead.

3 How the code works

The app is one file with a clean split between looks and audio. The window class never touches VLC internals; the engine class never touches Qt. That separation is what makes the app easy to restyle and easy to port.

3.1 The graceful import guard

import vlc

try:
    import vlc
except (ImportError, OSError):
    vlc = None

python-vlc is the only optional dependency. If it is missing, or if the VLC engine cannot be loaded at all, the window still opens - you get a clear dialog explaining what to install instead of a Python crash on startup. Every place that needs VLC checks vlc is None first. The OSError case matters for built apps: it is what a user without the bundled libvlc folder would hit.

3.2 Themes: JSON design tokens with fonts

THEMES_JSON + load_fonts_and_themes()

The whole look is driven by a JSON list of twenty-four themes: twelve dark themes followed by twelve light themes (light backgrounds, dark text). Each theme assigns four DIFFERENT fonts to four roles - brand (the SIONICAL RADIO wordmark), title (the station name and the marquee), body and wire (the wire-outline buttons) - each mapped to one of font1.ttf to font5.ttf from the components folder. Every theme also carries a palette of ten colors: background gradient ends, panel, border, accent pair, deep tone, text, glow, and icon color. Numbers that shape the design (window corner radius, equalizer opacity and tween speed, the two big font sizes, button diameters) are collected in an "EASY TWEAKS" constants block near the top of the file, so the look can be tuned without hunting through the code.

At startup, load_fonts_and_themes() registers the fonts with QFontDatabase.addApplicationFont() and applies theme 0. The wire THEME button (top right) displays the current theme's name and cycles through the list live - colors and fonts switch together, because the painted widgets read the current theme on every repaint.

To re-skin the entire app without touching code: create components/themes.json in the same shape; when present it replaces the embedded list entirely. Missing font files are no problem - the app falls back to the system font and keeps running.

3.3 parse_pls() - the .pls reader

def parse_pls(path)

A .pls file is a tiny INI-style playlist. The function reads it line by line and matches each one against ^(File|Title|Length)(\d+)\s*=\s*(.*)$ - that is, a key (File, Title, or Length), a station number, and a value.

Grouping is the clever part: entries.setdefault(idx, {...}) collects all lines belonging to the same station number into one dict, so File1 and Title1 merge into station 1, File2 and Title2 into station 2, and so on. It then returns the stations in order, giving each one a fallback name if the file has no Title line. If no playable URL was found, it raises ValueError, which the window turns into a friendly message box.

3.4 Painted widgets - gradients, bevels and tinted SVG icons

GradientButton, PlayCircleButton, VolumeBar, EqualizerWidget, SmallCircleButton

Everything stylish in the UI is hand-painted with QPainter inside each widget's paintEvent: the big play circle uses a radial gradient plus a glow, the buttons get a vertical gradient fill topped with a light glass bevel, the volume bar draws its own track, fill, and glowing handle. The three control circles and the station hearts instead load their artwork as SVG files from the components folder: svg_icon() renders each file and tints it with the current theme's colors (the SVGs are black-on-transparent), drawing the icons with 10 px of padding inside the circles. Painted shapes remain the built-in fallback when a file is missing, so the app never depends on an asset folder existing - and the icons stay crisp on any screen.

Because these widgets read the current theme's colors and fonts on every repaint, switching themes redraws them instantly with no bookkeeping.

The equalizer is real, not fake. StreamEngine runs a second, silent VLC player on the same URL whose audio output is a set of Python callbacks (libvlc's audio_set_callbacks + audio_set_format("S16N", 44100, 2)). VLC hands the visualizer the decoded PCM samples; a small pure-Python FFT (no numpy needed) turns each window of audio into band energies, and the bars move to the actual music. The 10 / 20 / 30 / 40 / 50 wire chips switch the bar count by re-slicing the same FFT output; each bar is a single rounded rectangle with no caps or markers on top.

The one trade-off. The silent analyser player means the stream is downloaded twice while playing (about 128 kbps extra). If a station refuses the second connection, or you set ENABLE_ANALYSER = False at the top of the file, the visualizer automatically falls back to a gentle idle animation while streaming - the music itself is never affected, because the audible player is a completely normal, untouched VLC player.

3.5 StreamEngine - the audio layer

class StreamEngine

This class is a thin, deliberate wrapper around libvlc:

  • vlc.Instance("--no-video") creates one VLC engine instance; media_player_new() creates the audible player.
  • play(url) makes a media object from the URL with media_new_location(), attaches it, and starts. Calling it again while playing simply switches stations - no stop needed. The silent analyser player (see 3.4) gets the same URL at the same time.
  • is_streaming() asks libvlc for its state and treats Opening, Buffering, and Playing as "we have signal". That is how the status line knows to say Streaming live. or Connection lost.
  • now_playing() reads the ICY metadata field that radio stations broadcast. The attribute is spelled NowPlaying or Nowplaying depending on the python-vlc version, so the module resolves it once with getattr and tolerates either.
  • The https metadata trap. VLC 3 plays https:// streams perfectly but only parses ICY "now playing" titles over plain http:// - its HTTPS access module drops the metadata blocks entirely (fixed only in VLC 4). Since nearly every station URL today is https, the silent analyser player connects over the plain-http twin of the URL (http_variant()), and now_playing() reads the title from whichever player has one: the audible player first, the analyser second. If a station offers no plain-http stream at all, check_analyser() - called by the heartbeat - notices the dead analyser after a couple of seconds and reconnects it on the original URL: the visualizer keeps working, and only the metadata stays missing.

Why VLC at all? Radio streams use many codecs and odd server quirks. libvlc already speaks MP3, AAC, AAC+, and OGG, handles redirects and ICY metadata, and has been battle-tested for two decades. Reimplementing that in pure Python would be a multi-month project; wrapping libvlc is one afternoon.

3.6 SionicalWindow - the GUI layer

class SionicalWindow(QMainWindow)

SionicalWindow
+-- PanelFrame  (paints the rounded window itself - 25 px corners - plus the glass panel inside; drag it to move the window)
+-- header:  [close][min][max]  Station name   |  SIONICAL RADIO  [THEME : NAME]
+-- marquee:  full-width scrolling "Artist - Song" line
+-- middle:  ( big play/stop circle over [mute][love][next] circles )  +  EQUALIZER [10|20|30|40|50] + live bars
+-- volume:  "VOLUME 80%"  + large painted volume bar
+-- stations_panel  (accordion: hidden until STATIONS arrow is clicked)
      each row:  [heart] Station name ... [x]
+-- bottom:  status text ....... [STATIONS v] [ADD PLS] [ADD STREAM]

Key mechanics worth knowing:

  • The accordion. The station list lives in a panel whose maximumHeight is animated between 0 and its full height by a QPropertyAnimation - that is the smooth expand/collapse when you click the STATIONS arrow. The arrow flips direction with the state.
  • The big circle is play AND stop. It reads the playing flag and swaps between a white triangle and a stop square; the painted icon always matches the engine state. Below it, three SmallCircleButtons (mute, love, next) share its gradient at 70% opacity; the love heart is the same shape and flag as the row hearts, and NEXT walks the displayed list order and wraps around.
  • Signals and slots. Qt's event wiring: open_pls_button.clicked.connect(self.on_open_pls) means "when clicked, call this method". Double-clicking a list item fires on_item_double_clicked; dragging the volume bar fires on_volume_changed.
  • The station model and its rows. Stations live in a plain list of dicts (self._stations); the QListWidget is only a view of it, rebuilt by rebuild_station_list() whenever anything changes. Each row starts with a heart - heart-filled.svg tinted with the accent color when the station is favorited (favorites always sort to the top), heart-outline.svg tinted with the text color when not - then the station name, then a thin X that removes the station (if it is currently playing, playback stops first). The stream URL is stored invisibly on the item with item.setData(Qt.UserRole, url) - a built-in per-item slot for arbitrary data - so double-click still works.
  • The frameless rounded window. The OS title bar is removed with Qt.FramelessWindowHint, and WA_TranslucentBackground lets PanelFrame paint the window itself as a smooth rounded rectangle (25 px corners) with genuinely transparent corners. Its three jobs are rebuilt inside the panel: WindowButton (macOS-style traffic lights) closes, minimizes and zooms the window from the header, and PanelFrame.mousePressEvent calls startSystemMove() so dragging the panel moves the window. Frameless windows cannot be edge-resized - use the green button to zoom/restore.
  • Drag and drop over the whole window. setAcceptDrops(True) plus the dragEnterEvent / dropEvent pair on the main window. The enter handler only accepts the drop if it is a local .pls file or an http URL; the drop handler routes it to the right place. A dropped .pls plays instantly.
  • The one-second heartbeat. A QTimer ticks every second and asks the engine "still streaming? any new track info?" and feeds the marquee label; URL-derived fake titles like "mp3-128" are filtered out (is_stream_junk()) so only real track info scrolls. The same tick calls engine.check_analyser(), which reconnects the silent analyser on the original URL if its plain-http twin failed to open (see 3.5). The equalizer runs its own faster timer (about 60 fps) that only reads the PCM tap - polling sounds unglamorous, but it keeps every widget update safely on the main GUI thread, which libvlc callbacks cannot promise.
  • Instant .pls. In __init__, if sys.argv[1] is an existing file, it is opened immediately - that is the "launch with a .pls, start streaming" behavior.

3.7 main() - the entry point

def main()

load_fonts_and_themes() registers the components fonts and the optional themes.json override, then the QApplication is created, the window shows, and Qt's event loop starts with app.exec(). From that moment on, the app is event-driven: it sleeps until you click something.

4 The .pls format, explained

.pls is the de-facto playlist format of internet radio. It is plain text with one block per station:

example .pls
[playlist]
File1=https://ice1.somafm.com/groovesalad-128-mp3
Title1=SomaFM Groove Salad
Length1=-1
File2=https://ice1.somafm.com/dronezone-128-mp3
Title2=SomaFM Drone Zone
Length2=-1
NumberOfEntries=2
Version=2
LineMeaning
FileNThe stream URL for station N. This is the line the player actually needs.
TitleNHuman-friendly station name shown in the UI.
LengthNTrack length in seconds. -1 means "live stream, never ends" - which is why radio .pls files are full of -1s.
NumberOfEntriesHow many stations the file lists. SionicalRadio does not rely on it; it counts the numbered lines itself.
Version=2Format version marker.

Radio stations usually publish a "Listen" or "Tune in" link that is actually a .pls file - download it and drop it onto the app.

5 Building installers for all 3 targets

The one rule: PyInstaller cannot cross-compile. You run the build once per target - on a Mac for the Mac builds (both architectures from one Mac), and on a Windows machine (or Windows VM) for the Windows build. The results are then distributable anywhere.
One-command rebuilds. Save the build scripts (from the download cards) in your project root and run chmod +x on them once. ./build-mac-intel.sh builds the Intel DMG, ./build-mac-silicon.sh the Apple Silicon DMG (both from the same Mac), and bash build-windows.sh in Git Bash on a Windows PC builds the Windows folder, ZIP and optional MSI; ./build-all.sh runs whatever the current machine can build. Every script does all of the steps below in one go: clean, PyInstaller build, launcher icon (from components/sionical-radio-logo.png), engine bundling, and re-signing. The sections that follow explain each step they perform.

5.1 Mac: one app for Intel AND Apple Silicon (universal2)

5.4 Bundle the VLC engine inside the installer (users need nothing)

python-vlc is only a remote control; the engine (libvlc) is what makes sound. The app ships with a small loader that checks for a libvlc folder next to its executable: if it finds one, it loads the engine from there and never looks at the user's system. So all you do is copy the engine in after the PyInstaller build:

macOS - copy the engine into the app bundle
APP=dist/SionicalRadio.app/Contents/MacOS
mkdir -p "$APP/libvlc"
cp -R /Applications/VLC.app/Contents/MacOS/lib/. "$APP/libvlc/"
cp -R /Applications/VLC.app/Contents/MacOS/plugins "$APP/libvlc/plugins"
install_name_tool -add_rpath @executable_path/libvlc "$APP/SionicalRadio"
codesign --force --deep --sign - dist/SionicalRadio.app

The last line matters: PyInstaller signs the app at the end of a build, and copying files into the bundle afterwards invalidates that signature - macOS then shows a circle-slash badge on the icon and refuses to open the app. The line re-signs the bundle ad-hoc (a free, local signature; fine for testing and Gatekeeper right-click > Open).

The install_name_tool line is not optional. VLC's dylibs reference each other as @rpath/libvlccore.dylib and carry no search path of their own - normally the VLC executable provides it. Your SionicalRadio binary must provide it instead, or macOS cannot load the bundled engine and the app dies at launch with Cannot load lib specified by PYTHON_VLC_LIB_PATH env. variable. The added rpath (@executable_path/libvlc) points at the folder you just copied, and also covers the plugin modules. If you use the build scripts (build-mac-intel.sh / build-mac-silicon.sh), this step is already inside them.
Windows - copy the engine next to the exe
xcopy /E /I "C:\Program Files\VideoLAN\VLC\plugins" "dist\SionicalRadio\libvlc\plugins"
copy "C:\Program Files\VideoLAN\VLC\libvlc.dll"     "dist\SionicalRadio\libvlc\"
copy "C:\Program Files\VideoLAN\VLC\libvlccore.dll" "dist\SionicalRadio\libvlc\"

How the loader works: it sets PYTHON_VLC_LIB_PATH (which python-vlc reads before loading anything), plus VLC_PLUGIN_PATH and PYTHON_VLC_MODULE_PATH so the engine finds its codec modules in the bundle. Without the folder - for example during development - the app simply uses your installed VLC like before. macOS bonus: VLC's dylibs are universal2, so one bundled engine covers Intel and Apple Silicon.

Two housekeeping notes. Size: expect the install to grow by roughly 150-250 MB - the price of shipping every codec. License: libvlc is LGPL, so include VLC's license text (a small LICENSE-vlc.txt next to the app is enough) and a link to videolan.org in your About or README, and keep the bundled engine updated with new releases since the VLC 3.0.x branch receives security fixes.

Why Windows builds use --onedir A one-file exe unpacks everything into a temp folder on every single launch; with 200 MB of engine files that means a slow start and heavy disk churn every run. With --onedir plus the Inno Setup installer, your users still receive one single Setup.exe - the installed app is simply a folder. On macOS the .app is already a folder bundle, so nothing changes there.

5.5 Signing: what those pop-ups are about

  • macOS Gatekeeper: unsigned apps are blocked on other people's Macs. For yourself: right-click the app, Open. For real distribution: an Apple Developer account (USD 99/year) lets you codesign + notarytool the app so it opens cleanly.
  • Windows SmartScreen: shows "Windows protected your PC" until the exe builds reputation or you buy a code-signing certificate. Users can click More info > Run anyway.

The universal2 one-app-for-both-Macs build (section 5.1) needs the manually installed universal2 interpreter, which is the route you use locally.

6 Troubleshooting

SymptomCause and fix
"python-vlc is not installed" dialogRun pip install -r requirements.txt in the active venv, and make sure VLC itself is installed on the machine.
Red underline on import vlc in PyCharmPackages went to the wrong interpreter. Set Settings > Project > Python Interpreter to your project venv and reinstall.
App opens but no soundCheck the volume slider, confirm VLC is installed, and try another station - some streams are region-restricted or temporarily down.
Built .app blocked on another Mac ("unidentified developer")Gatekeeper. Personal use: right-click the app and choose Open. Distribution: sign and notarize (section 5.5).
Windows shows "Windows protected your PC"SmartScreen on an unsigned exe. More info > Run anyway, or sign the exe.
Antivirus flags SionicalRadio.exeA known false-positive pattern with PyInstaller-built exe's (much rarer with the --onedir build used here). Signing the exe fixes it; submitting the file to the AV vendor also clears reputation.
Circle-slash badge on the SionicalRadio.app icon, app will not openCopying files into the bundle invalidated PyInstaller's signature. Re-sign it: codesign --force --deep --sign - dist/SionicalRadio.app
Built app dies at launch, terminal shows Cannot load lib specified by PYTHON_VLC_LIB_PATH env. variableThe bundled engine's dylibs find each other through an @rpath that nobody provides inside your app. Fix: install_name_tool -add_rpath @executable_path/libvlc dist/SionicalRadio.app/Contents/MacOS/SionicalRadio then re-sign (codesign --force --deep --sign - dist/SionicalRadio.app). Section 5.4 and the mac build scripts both include it.
Equalizer bars sway gently but never react sharply to beatsThe station refused the second (analyser) connection, or ENABLE_ANALYSER = False in the file. This is the designed fallback: the visualizer idles gracefully and sound is unaffected. Try another station to confirm.
Theme switching never changes the fontsFont files must sit in a components folder next to SionicalRadio.py (or next to the built executable), named exactly font1.ttf to font5.ttf. The app silently falls back to the system font when they are missing.
The marquee shows a bitrate like "mp3-128" instead of the artist and songThat text is not metadata - VLC invented it from the stream URL because the station never filled the ICY "now playing" field. The app filters such labels out (is_stream_junk()) and keeps the "Waiting for track info" line instead.
The marquee stays on "Waiting for track info from the station..." foreverTwo possibilities. 1) The copy of SionicalRadio.py predates the plain-http metadata fix: VLC 3 only parses ICY titles over plain http:// and drops them on https streams, so https stations need the analyser's plain-http twin (section 3.5). Copy the current source and retry. 2) The station truly broadcasts no ICY "now playing" field at all - not every station sends one; you can confirm what a station sends by opening its stream URL in the VLC desktop app and watching VLC's own window title. Also be patient on first play: stations only embed a metadata block every few seconds of audio, so the first title takes a few seconds to arrive.
The big panel looks the same washed-out gray in every theme (painted buttons still change)The window stylesheet lost its themed gradient. In Qt stylesheets, QWidget { background: transparent; } coming after the QMainWindow { background: ... } rule overrides the gradient, because QMainWindow is a QWidget subclass and the later rule wins on equal specificity - the platform then paints its default light gray. Keep the plain QWidget rule first and the QMainWindow rule last in build_qss(). The current code is already in that order.
The window cannot be moved by its top edge, or resized by dragging its edgesNormal for the frameless window: there is no OS title bar by design. Drag anywhere on the panel background to move the window, and use the green traffic light to zoom/restore. Frameless Qt windows have no edge-resize handles - that is the trade for the uniform, title-bar-free look (the same one Firefox and Sublime Text use).
Cannot find the close/minimize/maximize buttonsThey are the three small traffic-light circles at the top left of the panel (red, yellow, green), not in an OS title bar. The glyphs appear when you hover them.
Built app shows "Could not load the VLC engine" dialogNo libvlc folder next to the executable and VLC not installed on that machine. Redo the bundling step (section 5.4) and rebuild the installer.
universal2 build fails with an architecture errorYour Python is not the universal2 build (typical for Homebrew Pythons). Install Python 3.12 from the python.org universal2 installer and rebuild.
Built app flashes and closes instantlyRun it once from a terminal without --noconsole/--windowed to see the error message before packaging again.
